# 통합 테스트 시나리오 (14단계)

3~13단계 보고서에 각각 흩어져 있던 "사용자 확인 대기" 시뮬레이션 시나리오를
하나의 체크리스트로 통합했다. 개별 모듈 단위가 아니라, 여러 모듈이 동시에
관여하는 종단간(end-to-end) 시나리오 위주로 재구성했다. 최신 펌웨어
(`firmware/main.hex`, 14단계 기준)를 Proteus/SimulIDE에 로드한 뒤 아래
시나리오를 순서대로 실행하고 결과를 알려주면 이 문서와 관련 주차 보고서를
갱신한다.

## 공통 준비물

- ATmega128, 16MHz 클럭
- PF0: NTC 서미스터 + 10kΩ 분압 회로 (온도, 다이얼로 °C 설정)
- PF1: 가변 전압원 0~100V + 19k:1k 분압 (가스 센서 MQ-2 출력 0~5V 모사, 다이얼 숫자 = 농도 %)
- PD0: 풀업 스위치 (불꽃 센서 모사)
- PD1: 풀업 스위치 (테스트/리셋 버튼)
- PA0-PA2: LED 3개 (정상/주의/경보)
- PC0-PC5: 16x2 LCD (4비트 모드)
- PB5: 서보모터 (또는 서보 시뮬레이션 모델)
- PD4: 부저
- PE1(TXD0)/PE0(RXD0): 가상 터미널/UART 모니터 (9600bps, 8N1, 양방향)

## 시나리오 A — 기본 부팅 및 정상 상태

- 전원 인가 직후, 온도/가스를 모두 낮은 값(정상 범위)으로 둔다.
- 기대 결과: LED 정상(녹색) 점등, LCD 1행 `STATUS: NORMAL`, 2행에 현재
  온도/가스 값(`T:xxC G:xx%`) 표시, 서보 닫힘 위치, 부저 무음.

## 시나리오 B — 온도만 상승 (주의)

- 온도를 40°C 이상(서미스터 다이얼 45°C 정도)으로 올리고 가스/불꽃은 정상으로 유지한다.
- 기대 결과: LED 노랑으로 전환, LCD `WARN: HIGH TEMP` / `T:45C G:10%`(0.5초마다 갱신),
  부저 짧게 1회, 서보는 닫힘 유지(개방하지 않음), UART 메시지는 없음
  (경보/대피 상태에서만 전송).

## 시나리오 C — 가스만 상승 (경보)

- 가스를 50% 이상(가스 다이얼 60 정도)으로 올리고 온도/불꽃은 정상으로 유지한다.
- 기대 결과: LED 빨강, LCD `!! ALARM !!` / `Stand by`, 부저 짧게 1회,
  서보는 아직 닫힘 유지, UART로 `[경보] 가스 또는 온도 임계값 초과, 혹은
  불꽃 감지` 메시지 수신.

## 시나리오 D — 불꽃 감지 (즉시 경보, 9단계 회귀 확인 포함)

- 온도/가스는 정상 범위로 두고, PD0 스위치를 짧게 눌렀다 뗀다(불꽃 감지 모사).
- 기대 결과: 스위치를 누르는 즉시(약 100ms 이내) 경보 상태로 전환된다.
  스위치를 뗀 후에도 상태가 유지되며(9단계에서 고쳤던 "반복 트리거"
  버그와 12단계에서 고쳤던 "불꽃 조건 누락" 버그가 모두 해결됐는지 동시에
  확인하는 시나리오), LED/LCD가 한 번만 갱신되고 계속 깜빡이지 않는지 확인한다.
- 경보는 리셋 버튼을 누를 때까지 유지(래치)되므로, 그대로 두면 약 3초 뒤 대피로 격상된다.

## 시나리오 E — 경보 장시간 지속 → 대피 자동 격상

- 가스를 50% 이상으로 유지한 채(온도는 정상) 약 3초 이상 기다린다.
- 기대 결과: 약 3초 후 자동으로 대피 상태로 전환된다. LED는 계속 빨강,
  LCD `!! EVACUATE !!` / `EXIT NOW`, 서보가 열림 위치로 이동, 부저가
  0.1초 on/off 간격으로 3회 삑거린다(14단계에서 논블로킹으로 교체한
  패턴), UART로 `[대피] 화재 확정, 비상구 개방 - 즉시 대피 바랍니다` 메시지 수신.

## 시나리오 F — 온도+가스 동시 초과 → 즉시 대피

- 온도를 40°C 이상, 가스를 50% 이상으로 동시에 올린다.
- 기대 결과: 경보 단계를 거치지 않고(또는 매우 짧게 거치고) 즉시 대피
  상태로 전환된다(3초 대기 없이 즉시 격상).

## 시나리오 G — 테스트 버튼 리셋

- 임의의 상태(경보 또는 대피)에서 PD1 테스트 버튼을 짧게 누른다.
- 기대 결과: 즉시 정상 상태로 강제 복귀한다. 서보가 닫힘 위치로
  돌아가고, LCD/LED가 정상 상태 표시로 갱신되며, 울리던 부저도 바로 꺼진다.
- 가스나 온도가 아직 임계값 이상이면 다음 판단 주기(5ms)에 다시 경보로 들어간다.
  정상 복귀를 확인하려면 센서 값을 먼저 정상 범위로 내린 뒤 버튼을 누른다.

## 시나리오 H — 대피 중 반응성 확인 (14단계 핵심 검증)

- 시나리오 E와 동일하게 대피 상태에 진입시킨 직후(부저가 3회 삑거리는
  약 0.5~0.7초 구간 안에), PD1 테스트 버튼을 누른다.
- 기대 결과: 부저 패턴이나 UART 메시지 전송이 끝날 때까지 기다리지 않고,
  버튼을 누른 뒤 디바운싱 시간(20ms) 안에 정상 상태로 복귀한다. 만약 버튼 반응이 버저 패턴이
  끝날 때까지(최대 0.6초) 지연된다면, 14단계에서 고쳤다고 판단한 blocking
  문제가 실제로는 남아있다는 뜻이므로 재검토가 필요하다.

## 시나리오 I — 관제실 원격 명령 (양방향 통신)

- SimulIDE의 관제실 PC 창 **Send Text** 칸에 한 글자를 입력하고 Enter를 누른다. MCU의 회신은 왼쪽 Input 창(PC가 받은 글자)에, PC가 보낸 글자는 오른쪽 Output 창에 표시된다.
- 순서와 기대 결과:

| 순서 | 입력 | 기대 결과 |
|---|---|---|
| 1 | `S` | `STATE=NORMAL T=19C G=9%` 회신 |
| 2 | `T` | `OK TEST -> ALARM`, 빨강 LED와 `!! ALARM !!`, `[ALARM] ...` 메시지 |
| 3 | `T` (경보 중) | `ERR ALREADY ALARM` |
| 4 | 3초 대기 | 실제 화재와 같이 대피로 격상, 서보 개방, `[EVACUATE] ...` |
| 5 | `C` (대피 중) | `ERR EVACUATING - DOOR STAYS OPEN`, 서보는 열린 채 유지 (대피로 확보 우선) |
| 6 | `R` | `OK RESET`, 정상 복귀, 서보 닫힘, 부저 정지 |
| 7 | `O` → `C` | `OK DOOR OPEN` → `OK DOOR CLOSE`, 서보 열림 → 닫힘 |
| 8 | `x` | `ERR ? (S/R/T/O/C)` |

- 소문자도 같은 명령으로 처리한다. Enter(CR/LF)와 공백은 무시한다.

## 결과 기록

2026-11-18 실행 결과. 펌웨어는 같은 날 수정본(경보 래치, UART 인터럽트 송신) 기준.
SimulIDE는 `simulation/fire_gas_system.sim1`, simavr는 SimulIDE의 3바이트 복귀 주소 조건을 재현해 1ms 단위로 측정했다.
수정 과정은 `docs/troubleshooting-simulide.md` 문제 4~6 참조.

| 시나리오 | 결과 | 확인 방법 | 관찰 |
|---|---|---|---|
| A 기본 부팅 | 통과 | SimulIDE | 녹색 LED, `STATUS: NORMAL` / `T:19C G:9%` |
| B 온도만 상승 | 통과 | SimulIDE | 노랑 LED, `STATUS: WARNING` / `High temp!` |
| C 가스만 상승 | 통과 | SimulIDE, simavr | 빨강 LED, `!! ALARM !!` / `Stand by`, 터미널 `[ALARM] ...` |
| D 불꽃 감지 | 통과 (수정 후) | SimulIDE, simavr | 버튼을 뗀 뒤에도 경보 유지, 약 3초 뒤 대피. 수정 전에는 5ms 만에 정상 복귀 |
| E 대피 자동 격상 | 통과 | SimulIDE, simavr | 약 3초 뒤 `!! EVACUATE !!` / `EXIT NOW`, 서보 90° 개방, 터미널 `[EVACUATE] ...` |
| F 온도+가스 동시 | 통과 | SimulIDE, simavr | 경보를 거치지 않고 바로 대피 (SimulIDE: 50°C 상태에서 가스를 2.68V로 올리자 3초 대기 없이 `!! EVACUATE !!`) |
| G 리셋 버튼 | 통과 (수정 후) | SimulIDE, simavr | 대피 → 정상 복귀, 서보 닫힘, 부저 즉시 정지 |
| H 대피 직후 반응성 | 통과 (수정 후) | simavr | 대피 80ms 뒤 누른 버튼이 20ms 뒤 인식. 수정 전에는 UART 블로킹으로 약 70ms |
| I 관제실 원격 명령 | 통과 | SimulIDE, simavr | 1~8 모두 기대대로 회신. 명령 수신 후 5ms 안에 LED·서보 반영 (`T` 205→208ms, `R` 3704→3707ms) |

센서 교체 후 재확인 (2026-11-18): 온도를 NTC 서미스터, 가스를 전압원으로 바꾼 펌웨어로 simavr에서 A(20°C, 9%), B(45°C → 주의), C(가스 59% → 경보),
F(동시 초과 → 즉시 대피), G(관제실 `R` 복구), I(`S` 회신)를 다시 실행해 모두 같은 결과를 얻었다.

SimulIDE 전체 재확인 (2026-11-18, 센서 교체·양방향 통신 펌웨어): A(20°C, `T:20C G:9%`), B(서미스터 83°C → 주의), C(가스 2.81V → 경보),
D(불꽃 버튼을 뗀 뒤에도 경보 유지 → 약 3초 뒤 대피), E(가스 경보 → 3초 뒤 대피, 서보 개방, 가스를 0V로 내려도 대피 유지),
F(50°C + 가스 2.68V → 즉시 대피), G(복구 버튼 → 정상, 서보 닫힘), I(S·T·T·C·R·O·C·x·s 전부 기대대로 회신)를 화면으로 확인했다.
캡처: `docs/images/simulide/10`~`15`.

LCD 실시간 갱신·가스 % 다이얼 반영 후 재확인 (2026-11-19): 서미스터 60→45→25°C로 내리는 동안 LCD 2행이 `T:60C`→`T:45C`→`T:25C`로 따라오고
상태도 주의→정상으로 바뀌었다. 가스 다이얼 29.5 → `G:29%`, 45 → `G:45%`, 55 → 경보 → 3초 뒤 대피, 복구 버튼 → 정상(`T:25C G:45%`).
simavr 회귀 테스트도 타이밍은 그대로이고 가스 표시만 반올림으로 9% → 10%로 바뀌었다 (`simulation/simavr_regression_result.txt`).

H(대피 진입 80ms 뒤 버튼)는 사람 손으로 타이밍을 맞출 수 없어 simavr 측정 결과로만 근거를 남긴다.
같은 날 simavr로 A~I를 한 번에 돌리는 회귀 테스트에서도 H는 대피 106ms 뒤 누른 버튼이 18ms 뒤 인식됐다.
