# 발표자료 개요 — 화재·가스 감지 자동 대피 유도 시스템

발표 슬라이드 제작을 위한 구성 개요. 각 항목이 슬라이드 1장에 대응하도록 정리했다.

## 1. 표지
- 프로젝트명: 화재·가스 감지 자동 대피 유도 시스템
- 팀명, 팀원, 제출일

## 2. 프로젝트 배경 및 목표
- 화재 초기 징후(온도/가스/불꽃)를 빠르게 감지해 인명 피해를 줄이는 것이 목표
- ATmega128 기반 임베디드 시스템으로 구현

## 3. 시스템 개요 (블록다이어그램)
- `docs/architecture.md`의 블록다이어그램 삽입
- 입력: 온도(ADC0)/가스(ADC1)/불꽃(INT0)/테스트버튼(PD1)
- 출력: LED/LCD/부저/서보(비상구)/UART(관제실)

## 4. 동작 시나리오 (상태 기계)
- 정상 → 주의 → 경보 → 대피 4단계 상태와 전이 조건 표 (`docs/requirements.md` 5절)
- 상태별 LED/LCD/부저/서보/UART 동작 요약

## 5. 개발 과정 개요
- 15단계(주차) 순차 개발 방식 소개
- 각 단계: 기능 구현 → (의도적/통합) 오류 발생 → 재현 → 원인 분석 → 수정 → 검증

## 6. 대표 트러블슈팅 사례 1 — 클럭 가정 불일치
- 3단계(빌드), 10단계(타이머 프리스케일러), 13단계(UART 보드레이트)에서
  반복된 공통 패턴: "코드가 가정한 클럭"과 "실제 하드웨어 클럭"의 불일치
- 10단계 예시: 프리스케일러 64 선택 시 OCR0=1249가 8비트에 잘려 225로 저장,
  실제 주기가 목표(5ms) 대비 5.5배 빨라짐 → 프리스케일러 1024로 수정

## 7. 대표 트러블슈팅 사례 2 — 통합 중 조건 누락(회귀)
- 9단계에서 해결한 "불꽃 감지 반복 트리거" 문제가, 12단계에서 여러 센서
  판단 로직을 하나의 함수로 통합하는 과정에서 "불꽃 감지 조건 자체가
  누락"되는 형태로 재발
- 교훈: 개별 기능이 올바르게 동작해도 통합 리팩터링 시 조건이 빠질 수 있음

## 8. 대표 트러블슈팅 사례 3 — 통합 테스트로 발견한 타이밍 문제
- 14단계: 부저의 `_delay_ms()` 블로킹으로 대피 상태 진입 시 최대 600ms 동안
  센서 재평가/버튼 반응이 멈추는 문제를 통합 검토로 발견
- 논블로킹 타이머 기반 시퀀서로 교체, 호스트 테스트로 재검증

## 9. 검증 방법론
- 시뮬레이터(Proteus/SimulIDE) 없이도 검증 가능한 순수 로직(디바운싱,
  온도/가스 변환, 화재 판단, 부저 시퀀서 등)을 별도 모듈로 분리
- 호스트 환경에서 `make test`로 실행되는 단위 테스트 7종 소개
- 하드웨어 의존 모듈(ADC 기준전압, 타이머, UART 등)은 avr-gcc 컴파일
  경고/에러, `avr-objdump` 어셈블리 분석으로 검증

## 10. 최종 결과물
- 최종 리소스 사용량: Flash 2.7%, SRAM 6.1% (`docs/final-report.md` 6절)
- 전체 소스 `-Wall -Wextra` 무경고
- 통합 테스트 시나리오 A~H (`docs/test-scenarios.md`) 및 시연 영상/스크린샷 (있다면 삽입)

## 11. 한계 및 향후 개선
- LCD 갱신 시 잔여 블로킹(~5-8ms), 경보/대피 LED 공유, 예시 임계값 등
  (`docs/final-report.md` 7절 참조)
- UART 양방향 통신, 실제 센서 캘리브레이션 등 향후 확장 방향
