# 1주차 보고서 — 프로젝트 초기 설정 및 요구사항 정의

## 이번 주 목표

- 프로젝트 저장소(로컬 git) 초기화 및 기본 폴더 구조 구성
- 시스템 요구사항 명세서 작성 (입출력 정의, 동작 시나리오)

## 구현 내용

- `firmware/`, `docs/`, `reports/` 3개 디렉터리로 저장소 구조를 구성했다.
- `docs/requirements.md`에 다음 내용을 정리했다.
  - 입력: 온도 센서(ADC), 가스 센서(ADC, 채널 전환), 불꽃 센서(디지털, 외부 인터럽트), 테스트 버튼(GPIO)
  - 출력: 부저, 상태 LED, 서보모터(비상구, PWM), LCD, UART(관제실 통신)
  - 동작 상태를 정상/주의/경보/대피 4단계로 정의하고 각 단계의 진입 조건과 시스템 동작을 표로 정리했다.
  - 성능 요구사항(인터럽트 반응 시간, 디바운싱 시간, 보드레이트 등)의 잠정값을 명시하고, 각 값의 최종 확정 시점(해당 단계)을 함께 표기했다.
- 이번 주는 코드 구현이 아닌 설계/문서화 단계이므로 레지스터나 주변장치 선택은 아직 이루어지지 않았다. 구체적인 핀 할당과 회로 구성은 2단계에서 진행한다.

## 발생한 오류 및 트러블슈팅 과정

이번 주는 문서화 단계로, 의도적 오류 삽입 대상 코드가 없다. 의도적 오류 삽입은
3단계(개발 환경 구축, 빌드/퓨즈 설정 오류)부터 시작한다.

## 시뮬레이션 검증 결과

이번 주는 시뮬레이션 대상 코드가 없어 해당 없음. 요구사항 명세서의 검증 범위(7절)에서
정의한 시나리오(정상→주의→경보→대피 상태 전이)를 앞으로의 단계에서 순차적으로 검증할 예정이다.
