# 7주차 보고서 — ADC 온도 센서 읽기

## 이번 주 목표

- ADC0(PF0)로 아날로그 온도 센서 값을 읽는 드라이버 구현
- ADC 원시값을 섭씨 온도로 변환하는 로직 구현
- ADC 기준전압/분주비 설정 오류 재현 및 수정

## 구현 내용

- `firmware/adc.h`/`adc.c`: `ADMUX`(기준전압/채널 선택)와 `ADCSRA`(ADC 활성화,
  분주비, 변환 시작)를 설정하는 `adc_init()`과, 지정한 채널을 블로킹 방식으로
  변환해 10비트 값을 반환하는 `adc_read(channel)`을 구현했다.
  - 분주비: `ADPS2:0 = 111`(분주비 128) → ADC 클럭 = 16MHz/128 = 125kHz로,
    10비트 변환 정확도를 보장하는 권장 범위(50~200kHz) 안에 들어간다.
  - 기준전압: `REFS1:0`으로 선택하며, 이번 주 의도적 오류의 대상이다(아래 참조).
- `firmware/temp.h`/`temp.c`: ADC 원시값을 섭씨 온도로 변환하는 순수 함수
  `adc_to_temp_c()`를 구현했다. AVCC(5V) 기준전압과 LM35 계열 아날로그 온도
  센서(10mV/°C, 0V=0°C)를 가정해 `temp = raw * 500 / 1024`로 계산한다.
  AVR 레지스터에 의존하지 않는 순수 C 함수라서 호스트 환경에서도 단위 테스트가
  가능하다.
- `main.c`: `gpio_init()`에서 `adc_init()`을 호출하고, 정상 상태로 진입할
  때마다 `adc_read(0)` → `adc_to_temp_c()`로 온도를 구해 LCD 2행에
  `TEMP: NN C` 형식으로 표시하도록 연결했다.
- `firmware/tests/test_temp.c`: 호스트 단위 테스트를 추가했다. 실제 ADC
  하드웨어가 주어진 기준전압 하에서 어떤 카운트 값을 낼지 계산하는
  `mock_adc_raw()`로, 동일한 센서 전압(25°C 가정, 250mV)을 서로 다른
  기준전압(AVCC 5V vs 내부 2.56V) 조건에서 시뮬레이션하고 `adc_to_temp_c()`로
  변환한 결과를 비교한다.

## 발생한 오류 및 트러블슈팅 과정

**증상**: `adc.c`의 `adc_init()`에서 `ADMUX = (1 << REFS1) | (1 << REFS0);`로
내부 2.56V 기준전압을 선택했다. 그런데 `temp.c`의 변환 공식은 AVCC(5V) 기준을
가정하고 있어, 둘 사이에 불일치가 생겼다. 이를 확인하기 위해
`tests/test_temp.c`에서 실제 상온(25°C, 센서 출력 250mV)을 두 기준전압
시나리오로 각각 시뮬레이션했다.

```
$ make test
...
실제 센서 온도: 25 C
AVCC(5V) 기준 설정 시 계산된 온도: raw=51 -> 24 C
내부 2.56V 기준(버그) 설정 시 계산된 온도: raw=100 -> 48 C
PASS
```

실제 25°C인 상온이 48°C로 계산되어 약 24°C의 오차가 발생했다. 이 상태로는
평상시에도 "주의" 단계(온도 임계값 초과)가 잘못 트리거될 수 있는 심각한
오동작이다.

**원인 분석**: 기준전압이 낮을수록(2.56V < 5V) 동일한 센서 전압이 기준전압에서
차지하는 비율이 커지므로, ADC 카운트 값이 실제보다 크게 나온다(raw=51 → raw=100,
약 2배). `temp.c`의 변환 공식은 이 카운트 값을 그대로 5V 기준으로 해석하므로,
실제보다 카운트가 큰 만큼 온도도 실제보다 높게 계산된다. 즉 "코드 변환 공식이
가정하는 기준전압"과 "레지스터에 실제로 설정된 기준전압"이 서로 다른 모듈
간에 암묵적으로 공유되는 가정이었는데, 이 가정이 깨진 것이 근본 원인이다.

**해결 과정**:
1. `temp.c`의 변환 공식이 AVCC(5V) 기준을 전제로 작성되어 있음을 코드 주석과 요구사항 문서를 통해 재확인했다.
2. `adc.c`의 `ADMUX` 초기화를 `REFS1:0 = 01`(AVCC 기준)로 수정했다.
3. `avr-objdump -d main.elf`로 `adc_init()`의 첫 명령이 `ldi r24, 0x40`(0b01000000, REFS0 비트만 설정)으로 생성됨을 확인했다.
4. `tests/test_temp.c`를 재실행해 AVCC 기준(raw=51 → 24°C)이 실제 온도(25°C)에 근접함을 재확인했다.

## 시뮬레이션 검증 결과

**확인해야 할 시뮬레이션 시나리오** (Proteus/SimulIDE):
1. PF0에 가변저항(또는 온도 센서 모델)을 연결해 0~5V 범위의 아날로그 입력을 구성한다.
2. 입력 전압을 250mV(약 25°C 상당)로 맞추고 `main.hex`(수정 후, `e1924c0` 커밋)를 실행한다.
3. 테스트 버튼을 눌러 정상 상태로 돌아왔을 때 LCD 2행에 `TEMP: 24 C` 근처 값이 표시되는지 확인한다.
4. 입력 전압을 서서히 올리며 표시되는 온도값이 전압 변화에 비례해 선형적으로 증가하는지 확인한다.

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (기준전압 버그와 수정 자체는 `make test` 호스트 단위 테스트로 결정적으로 검증 완료했습니다.)
