# 11주차 보고서 — 서보모터 PWM 제어(비상구 자동 개방)

## 이번 주 목표

- Timer1(OC1A, PB5)로 50Hz 서보 PWM 신호 생성
- 경보 상태에서 비상구(서보)를 자동으로 개방, 그 외 상태에서는 닫힘 유지
- PWM 듀티 계산 오류로 인한 서보 떨림 재현 및 수정

## 구현 내용

- `servo_init()`: `DDRB`에서 `PB5`(OC1A)를 출력으로 설정하고, `ICR1`을
  TOP(`SERVO_TOP=39999`)으로 하는 Fast PWM 모드(`WGM13:10 = 1110`)를 구성했다.
  분주비는 8(`CS11`)로 설정해 `16MHz/8/(39999+1) = 50Hz`(20ms 주기)를 만든다.
- `servo_angle_to_ocr1a(angle_deg)`: 0~180도를 `OCR1A`에 넣을 타이머 카운트로
  변환하는 순수 함수로 분리했다(AVR 레지스터에 의존하지 않아 호스트 테스트 가능).
- `servo_open()`/`servo_close()`: 각각 90도/0도에 해당하는 카운트를 `OCR1A`에
  대입한다. `show_state()`에서 `STATE_ALARM`일 때 `servo_open()`, 그 외
  (`STATE_NORMAL`, `STATE_WARNING`)일 때 `servo_close()`를 호출하도록 연결했다.
  (경보/대피를 아직 하나의 `STATE_ALARM`으로 통합해 다루고 있으며, 세분화된
  상태 기계는 12단계에서 구현한다.)

## 발생한 오류 및 트러블슈팅 과정

**증상**: 초기 구현에서 `servo_angle_to_ocr1a()`는 각도를 PWM **전체 주기**
(`SERVO_TOP`, 20ms)에 대한 듀티비로 직접 매핑했다:
`OCR1A = angle_deg * SERVO_TOP / 180`. 이를 호스트 단위 테스트
(`tests/test_servo_pwm.c`)로 검증한 결과는 다음과 같다.

```
$ make test
...
angle=  0 deg | 버그:     0.0 us | 수정:  1000.0 us (유효 범위 1000~2000 us)
angle= 90 deg | 버그:  9999.5 us | 수정:  1500.0 us (유효 범위 1000~2000 us)
angle=180 deg | 버그: 19999.5 us | 수정:  2000.0 us (유효 범위 1000~2000 us)
```

우리 시스템이 실제로 사용하는 두 각도(닫힘=0도, 개방=90도)에서 모두 문제가
드러났다: 0도는 펄스 폭이 0us(사실상 신호 없음), 90도는 9999.5us로 유효
범위(1000~2000us)의 약 10배에 달했다.

**원인 분석**: 일반적인 LED 밝기 조절 PWM에서는 "듀티비 0~100%가 곧 밝기
0~100%"라는 감각이 자연스럽다. 하지만 RC 서보모터는 그렇게 동작하지 않는다.
서보는 20ms 주기 자체가 아니라, 그 주기 안의 **1~2ms라는 좁은 펄스 폭**만으로
목표 각도를 해석하도록 설계되어 있다(1ms=0도, 1.5ms=90도, 2ms=180도가 일반적인
규격). "각도를 전체 주기에 대한 비율로 매핑"한 것은 LED PWM의 직관을 서보
제어에 잘못 적용한 것으로, 서보 입장에서는 유효 범위를 크게 벗어난 신호를
받게 되어 기계적 한계에서 떨거나(buzz) 위치를 제대로 잡지 못하는 오동작으로
이어질 수 있다.

**해결 과정**:
1. RC 서보 표준 제어 규격(20ms 주기, 1~2ms 펄스 폭)을 확인했다.
2. `servo_angle_to_ocr1a()`를 "각도 → 펄스 폭(1000~2000us) → 타이머 카운트"의
   2단계 변환으로 다시 작성했다: 먼저 `pulse_us = 1000 + angle_deg * 1000 / 180`으로
   유효 펄스 폭을 구하고, 이를 `SERVO_TICKS_PER_US`(마이크로초당 2틱, 분주비 8·2MHz
   기준)로 곱해 최종 `OCR1A` 값을 얻는다.
3. `tests/test_servo_pwm.c`로 재검증한 결과, 각도 0/90/180도 모두 계산된
   펄스 폭이 1000~2000us 유효 범위 안에 들어옴을 확인했다.

## 시뮬레이션 검증 결과

**확인해야 할 시뮬레이션 시나리오** (Proteus/SimulIDE):
1. PB5(OC1A)에 서보모터(또는 서보 시뮬레이션 모델)를 연결한다.
2. 수정 전(`91c3de5` 커밋) `.hex`를 로드해 실행 → 테스트 버튼으로 경보 상태에 진입했을 때 서보가 떨거나(buzz) 비정상적으로 끝까지 돌아가려 하는지 확인
3. 수정 후(`84d170e` 커밋) `.hex`를 로드해 실행 → 경보 상태 진입 시 서보가 부드럽게 열림 위치(약 90도)로 이동하고, 정상/주의 상태로 돌아오면 닫힘 위치(0도)로 복귀하는지 확인
4. (가능하다면) 오실로스코프/로직 분석기로 OC1A 핀의 펄스 폭이 약 1.0ms(닫힘)와 1.5ms(열림) 근처인지 직접 측정

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (각도-펄스폭 변환 계산 자체는 호스트 단위 테스트로 결정적으로 검증 완료했습니다.)
