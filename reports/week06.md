# 6주차 보고서 — LCD 디스플레이 연동

## 이번 주 목표

- HD44780 호환 16x2 LCD를 4비트 모드로 구동하는 드라이버 작성
- 상태(정상/주의/경보) 전환 시 LCD에 상태 메시지 표시
- 초기화 시퀀스 오류로 인한 화면 깨짐 재현 및 수정

## 구현 내용

- `firmware/lcd.h`/`lcd.c`: PORTC(PC0=RS, PC1=E, PC2-PC5=D4-D7, RW은 GND 고정)를
  사용한 4비트 모드 LCD 드라이버를 작성했다. `lcd_write_nibble()`로 4비트씩 두 번
  나눠 보내 한 바이트(`lcd_write_byte()`)를 전송하고, 이를 기반으로
  `lcd_command()`/`lcd_data()`/`lcd_string()`/`lcd_set_cursor()`/`lcd_clear()`를
  구현했다.
- `main.c`의 `show_state()`에 LCD 출력을 추가해, 상태가 바뀔 때마다 LCD를
  지우고 1행에 상태명, 2행에 안내 문구를 표시하도록 했다.
  - 정상: `STATUS: NORMAL` / `System OK`
  - 주의: `STATUS: WARNING` / `Check sensors`
  - 경보: `!! FIRE ALARM !!` / `EVACUATE NOW`
- **설계 상 주의사항**: HD44780의 내장 폰트 ROM(대개 A00 타입)은 영문/숫자/기호와
  일본어 가타카나만 지원하고 한글(Hangul)은 지원하지 않는다. 이는 요구사항
  명세서에서 한글로 작성했던 상태 문구를 LCD에 그대로 출력할 수 없다는 뜻이므로,
  LCD 표시 문구는 영문으로 작성했다. (사용자에게 보여주는 UART 메시지나 보고서는
  한글을 그대로 사용한다.)

## 발생한 오류 및 트러블슈팅 과정

**증상**: HD44780 데이터시트에 따르면, 컨트롤러는 전원 인가 직후 8비트
인터페이스를 기본으로 가정한다. `lcd_init()`에서 전원 안정화 대기(20ms) 후
곧바로 4비트 Function Set 명령(`0x28`)을 니블 단위(상위 `0x2`, 하위 `0x8`)로
전송했는데, 컨트롤러 입장에서는 아직 4비트 모드로 전환된 상태가 아니므로 이
니블들을 의도와 다르게(8비트 명령의 일부 또는 잘못된 정렬로) 해석하게 된다.
이후 모든 명령/데이터의 니블 정렬이 어긋나 화면에 깨진 문자가 나타나거나
초기화가 아예 실패하는 증상이 예상된다.

**원인 분석**: HD44780을 4비트 모드로 초기화하려면, 정식 명령 전송에 앞서
데이터시트가 규정한 특수 "웨이크업" 절차가 필요하다: RS=0 상태에서 `0x3`
니블을 세 번(각각 지정된 지연시간을 두고), 이어서 `0x2` 니블을 한 번 단독으로
전송해야 컨트롤러가 비로소 4비트 인터페이스로 전환된다. 이 절차 없이 곧바로
`Function Set`을 보낸 것이 원인이다. 이는 8비트 모드 초기화 코드(웨이크업 절차
없이 바로 명령 전송 가능)를 4비트 모드에 그대로 적용하려다 발생하는, 실제로
매우 흔한 HD44780 초심자 실수다.

**해결 과정**:
1. HD44780 데이터시트 기준 4비트 모드 초기화 절차를 확인했다.
2. `lcd_init()`에서 전원 안정화 대기 직후, `Function Set` 명령 이전에
   `lcd_write_nibble(0x03)`을 세 번(각각 5ms, 150us, 150us 지연), 이어서
   `lcd_write_nibble(0x02)`를 추가해 웨이크업 시퀀스를 완성했다.
3. `avr-objdump -d main.elf`로 컴파일된 명령을 확인해, `lcd_write_nibble` 호출
   직전에 `ldi r24, 0x03`이 3회 생성된 것을 확인했다 — 웨이크업 니블 3회
   전송이 코드에 의도대로 반영되었음을 정적으로 검증했다.

## 시뮬레이션 검증 결과

**확인해야 할 시뮬레이션 시나리오** (Proteus/SimulIDE):
1. ATmega128에 16x2 LCD(HD44780 호환)를 PC0-PC5에 연결하고(RW은 GND), 대비(V0) 전압을 적절히 설정한다.
2. 수정 전(`9258801` 커밋) `.hex`를 로드해 실행 → 화면이 깨지거나(사각형 나열, 의미 없는 문자) 아무것도 표시되지 않는지 확인
3. 수정 후(`1425b3d` 커밋) `.hex`를 로드해 실행 → 전원 인가 직후 1행에 `STATUS: NORMAL`, 2행에 `System OK`가 정상적으로 표시되는지 확인
4. 테스트 버튼을 눌러 주의/경보 상태로 전환하면서 LCD 문구가 올바르게 갱신되는지 확인

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (초기화 니블 시퀀스 자체는 objdump로 코드 레벨에서 확정적으로 검증했습니다.)
