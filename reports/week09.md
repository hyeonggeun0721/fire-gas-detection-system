# 9주차 보고서 — 불꽃 센서(디지털 입력) 및 외부 인터럽트 처리

## 이번 주 목표

- PD0(INT0)에 불꽃 센서를 연결하고 외부 인터럽트로 즉시 반응하도록 구현
- 인터럽트 플래그 미처리로 인한 반복 트리거 재현 및 수정

## 구현 내용

- `gpio_init()`에 불꽃 센서 핀(PD0) 설정을 추가했다. 입력 모드를 유지하고
  내부 풀업을 활성화해, 불꽃 미감지 시 HIGH, 감지 시 LOW로 출력하는 센서를
  가정했다(일반적인 IR 불꽃 감지 모듈의 활성-LOW 디지털 출력 방식).
- `EICRA`의 `ISC01:ISC00 = 10`으로 하강 엣지(HIGH→LOW) 트리거를 설정하고,
  `EIMSK`의 `INT0` 비트를 설정해 인터럽트를 활성화했다. 화재는 반응 속도가
  중요하므로(요구사항 명세서 6절: 불꽃 감지 반응 100ms 이내), 폴링 대신
  하드웨어 인터럽트를 사용하는 2단계 아키텍처 설계를 그대로 구현했다.
- `ISR(INT0_vect)`는 `volatile uint8_t flame_detected` 플래그만 세팅하고 즉시
  반환하도록 최소화했다(ISR 안에서 LCD 갱신 등 무거운 작업을 하지 않는 것이
  일반적인 관례). 실제 처리(상태 전환, LED/LCD/부저 갱신)는 메인 루프에서
  플래그를 검사해 수행한다.
- `main()`에 `sei()`를 추가해 전역 인터럽트를 활성화했다.

## 발생한 오류 및 트러블슈팅 과정

**증상**: 메인 루프가 `flame_detected` 플래그를 검사해 경보 상태로 전환하는
코드는 작성했지만, 처리 후 플래그를 0으로 되돌리는 코드가 빠져 있었다. 이
패턴(ISR이 플래그를 세팅하고, 메인 루프가 매 틱마다 플래그를 검사해 동작을
수행)을 호스트 단위 테스트(`tests/test_interrupt_flag.c`)로 그대로 재현했다.
5ms 주기 루프를 200틱(약 1초) 돌리면서 50번째 틱에서 인터럽트가 1회
발생한다고 가정했다.

```
$ make test
...
총 루프 틱 수: 200, 불꽃 감지(ISR)는 50번째 틱에서 1회 발생
플래그 리셋 없음(버그) - 경보 처리 실행 횟수: 150
플래그 리셋 있음(수정) - 경보 처리 실행 횟수: 1
```

물리적으로 단 한 번 발생한 불꽃 감지 이벤트가, 리셋 누락 상태에서는 남은 모든
루프 틱(150회)마다 경보 처리 블록을 반복 실행시키는 것으로 나타났다.

**원인 분석**: AVR의 외부 인터럽트 플래그(`EIFR`의 `INTF0` 비트)는 ISR이
실행되면 하드웨어가 자동으로 클리어해준다. 하지만 이번에 사용한
`flame_detected`는 그와 별개로 ISR이 세팅하는 **소프트웨어 플래그**이고, 이
플래그를 사용한 뒤 원상 복구하는 책임은 전적으로 프로그래머(메인 루프 코드)에게
있다. "물리적으로 한 번 발생한 인터럽트 이벤트"와 "메인 루프가 도는 동안
계속 유지되는 소프트웨어 상태값"을 혼동해 리셋을 빠뜨린 것이 원인이다. 이
상태로는 부저가 멈추지 않고 계속 울리며, LCD가 매 루프마다 지우고 다시 쓰기를
반복(화면 깜빡임)하고, 무엇보다 `state`가 매 루프마다 강제로 `STATE_ALARM`으로
재설정되어 테스트 버튼으로도 경보 상태를 벗어날 수 없는 심각한 오동작으로
이어질 수 있었다.

**해결 과정**:
1. `flame_detected` 플래그가 세팅된 이후 한 번도 리셋되지 않는다는 것을 코드
   리뷰로 확인했다.
2. 동일한 검사-처리 패턴을 호스트 테스트로 추출해, 리셋 유무에 따른 처리
   횟수 차이를 정량적으로 재현했다.
3. `main.c`의 처리 블록에 `flame_detected = 0;`을 추가해, 플래그를 사용한
   직후 즉시 리셋하도록 수정했다.
4. `make test`로 재검증한 결과, 경보 처리 횟수가 정확히 1회로 정상화됨을 확인했다.

## 시뮬레이션 검증 결과

**확인해야 할 시뮬레이션 시나리오** (Proteus/SimulIDE):
1. PD0에 풀업 스위치(또는 불꽃 센서 모델)를 연결한다(평상시 HIGH, 누르면/감지되면 LOW).
2. 수정 전(`202c3ef` 커밋) `.hex`를 로드해 실행 → 스위치를 짧게 한 번 눌렀다 떼도 부저가 계속 울리고 LCD가 계속 깜빡이며, 테스트 버튼을 눌러도 경보 상태에서 벗어나지 못하는지 확인
3. 수정 후(`a3f5c92` 커밋) `.hex`를 로드해 실행 → 스위치를 짧게 한 번 누르면 경보 상태로 전환된 뒤 정상적으로 유지되고(반복 재출력 없음), 이후 테스트 버튼으로 정상/주의 상태로 전환 가능한지 확인

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (플래그 리셋 누락과 수정 자체는 `make test` 호스트 단위 테스트로 결정적으로 검증 완료했습니다.)
