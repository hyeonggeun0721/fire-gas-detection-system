# 5주차 보고서 — 테스트 버튼 입력 및 디바운싱

## 이번 주 목표

- 테스트 버튼(PD1) 입력 처리 및 정상/주의/경보 상태 순환 로직 구현
- 디바운싱 미적용으로 인한 중복 입력 재현 및 수정
- 하드웨어/시뮬레이터 없이도 로직을 검증할 수 있는 호스트 단위 테스트 도입

## 구현 내용

- `gpio_init()`에 버튼 핀(PD1) 설정을 추가했다. `BUTTON_DDR &= ~BUTTON_PIN`으로
  입력 모드를 유지하고 `BUTTON_PORT |= BUTTON_PIN`으로 내부 풀업 저항을 활성화해,
  버튼 미입력 시 HIGH, 누르면 LOW가 되는 활성-LOW 방식으로 구성했다.
- 버튼을 누를 때마다 `system_state_t`(정상→주의→경보→정상)가 순환하고,
  `show_state()`가 해당 상태에 맞춰 LED/부저를 갱신하도록 구현했다. 이는 12단계에서
  구현할 실제 센서 기반 상태 기계의 입력을 임시로 버튼으로 대체한 것으로,
  요구사항 명세서 7절의 "테스트/리셋 버튼: 시뮬레이션 시나리오 수동 트리거용" 목적에 부합한다.
- `firmware/debounce.h`/`debounce.c`: AVR 레지스터에 의존하지 않는 순수 C 로직으로
  카운터 기반 디바운싱을 구현했다. 원시 입력이 `DEBOUNCE_THRESHOLD`(4회)만큼
  연속으로 같은 값을 유지해야 안정 상태로 인정한다. 메인 루프의 샘플링 주기가
  5ms이므로 4 × 5ms = 20ms로, 요구사항 명세서 6절에서 정한 최소 디바운싱
  시간(20ms)과 일치하도록 값을 선택했다.
- `firmware/tests/test_debounce.c`: 일반 gcc로 빌드되는 호스트 단위 테스트를 추가했다.
  실제 기계식 버튼의 바운스 파형을 흉내낸 원시 입력 시퀀스를 만들어, (1) 디바운싱
  없이 엣지를 검출하는 기존 방식과 (2) `debounce.c`를 통과시킨 방식의 press 카운트를
  비교한다. `firmware/Makefile`에 `make test` 타깃을 추가해 시뮬레이터 없이 바로
  실행할 수 있게 했다.

## 발생한 오류 및 트러블슈팅 과정

**증상**: 버튼을 물리적으로 1회 눌러도, 기계식 스위치 접점이 짧은 시간 동안
여러 번 붙었다 떨어지는 "바운스" 현상 때문에 여러 번 눌린 것으로 잘못 인식될
가능성이 있다. 이를 확인하기 위해 5ms 샘플링 주기 기준으로 바운스 파형을
흉내낸 입력 시퀀스를 만들고, `tests/test_debounce.c`에 Week05 기능 커밋(버그
포함) 당시의 로직(디바운싱 없이 원시 신호로 바로 엣지 검출)을 `naive_press_count()`로
그대로 재현해 동일한 시퀀스에 통과시켰다.

```
$ make test
naive (디바운싱 없음) 감지된 press 횟수: 4
```

물리적으로 1번 누른 입력이 4번으로 잘못 카운트되어, 상태가 정상→주의→경보→정상→주의로
버튼 한 번에 4단계나 건너뛰는 오동작이 예상된다.

**원인 분석**: `main.c`가 `PIND`에서 읽은 원시 신호를 이전 값과 직접 비교해
HIGH→LOW 전환을 엣지로 판단하고 있었다. 그런데 바운스 구간에서는 원시 신호가
짧은 시간 안에 HIGH/LOW를 여러 번 오가기 때문에, 이 전환들이 모두 독립적인
버튼 입력으로 처리되었다. 즉, "버튼을 눌렀다"는 물리적 사건과 "신호가
HIGH에서 LOW로 바뀌었다"는 전기적 사건을 동일시한 것이 근본 원인이다.

**해결 과정**:
1. `debounce.h`/`debounce.c`에 카운터 기반 디바운싱 모듈을 작성했다. 원시 입력이
   같은 값을 `DEBOUNCE_THRESHOLD`회 연속 유지해야만 `stable_state`를 갱신한다.
2. `main.c`가 원시 신호 대신 `debounce_update()`가 반환한 안정 상태를 기준으로
   엣지를 검출하도록 수정했다.
3. `tests/test_debounce.c`로 동일한 바운스 시퀀스를 다시 검증했다.

```
$ make test
naive (디바운싱 없음) 감지된 press 횟수: 4
debounce.c 적용 후 감지된 press 횟수: 1
PASS
```

수정 후 동일한 바운스 입력에 대해 press 횟수가 1로 정상화됨을 확인했다.

## 시뮬레이션 검증 결과

이번 주 로직 검증은 호스트 단위 테스트(`make test`)로 결정적으로(deterministic)
확인했다. Proteus/SimulIDE의 이상적인(ideal) 스위치 모델은 실제 기계식 버튼과
달리 바운스가 발생하지 않는 경우가 많아, 시뮬레이터만으로는 이번 버그를
재현하기 어려울 수 있다.

**확인해야 할 시뮬레이션 시나리오**:
1. PD1에 풀업 스위치를 연결하고, PA0-2/PD4를 4단계와 동일하게 연결한다.
2. `main.hex`를 로드해 실행하고, 버튼을 한 번 클릭할 때마다 LED가 정확히
   한 단계씩(정상→주의→경보→정상) 전환되는지 확인한다.
3. (스위치 바운스 모델을 지원하는 경우) 바운스가 있는 스위치 모델로 교체해
   1회 클릭 시에도 상태가 여러 단계 건너뛰지 않는지 확인한다.

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (디바운싱 로직 자체의 정확성은 `make test`로 결정적으로 검증 완료했습니다.)
