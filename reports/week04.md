# 4주차 보고서 — GPIO 기초 (LED/부저 출력 제어)

## 이번 주 목표

- 상태 LED(PA0-2)와 부저(PD4)에 대한 GPIO 출력 제어 코드 작성
- DDRx/PORTx 설정 관련 흔한 실수 재현 및 수정

## 구현 내용

- `gpio_init()`에서 부저 핀(PD4)을 출력으로 설정하고 초기값을 OFF로 둔다.
- `main()`의 무한 루프에서 정상(PA0) → 주의(PA1) → 경보(PA2, 부저 동반)
  순서로 1초씩 순환 점등하는 데모 로직을 작성했다. 이는 실제 센서 연동 전
  출력 하드웨어(LED/부저)가 배선대로 동작하는지 확인하기 위한 테스트 코드다.
- 레지스터 선택 이유: PORTA/PORTD는 2단계 핀맵에서 이미 LED/부저용으로
  할당되어 있어 그대로 사용했다. AVR의 GPIO 출력 제어는 DDRx(방향)와
  PORTx(값) 두 레지스터를 모두 설정해야 완성된다.

## 발생한 오류 및 트러블슈팅 과정

**증상**: 빌드는 정상적으로 성공한다(문법 오류 없음). 그러나 코드를 분석한 결과
LED 출력이 의도대로 동작하지 않을 것으로 예상되어, 실행 전 `avr-objdump`로
생성된 어셈블리를 점검했다.

```
$ avr-objdump -d main.elf | grep -E "0x1a|0x1b"
  ac: 8b bb  out 0x1b, r24   ; PORTA
  b2: 8b bb  out 0x1b, r24   ; PORTA
  b4: d8 9a  sbi 0x1b, 0     ; PORTA
  ...
```

PORTA(I/O 주소 0x1b)에 값을 쓰는 명령은 다수 존재하지만, **DDRA(I/O 주소 0x1a)에
접근하는 명령이 단 한 줄도 없었다.**

**원인 분석**: `gpio_init()`에서 부저용 `BUZZER_DDR |= BUZZER_PIN;`(DDRD 설정)은
작성했지만, LED용 `LED_DDR |= LED_ALL;`(DDRA 설정)을 빠뜨렸다. AVR은 리셋 시
모든 DDRx 레지스터가 0(입력 모드)으로 초기화되므로, PA0-2는 여전히 입력 핀으로
남아있는 상태다. 이 상태에서 `PORTx`에 값을 쓰면 핀을 능동적으로 구동(source/sink)하는
것이 아니라 내부 풀업 저항을 켜고 끄는 것에 불과하다. 결과적으로 외부 LED에는
풀업 저항(수십 kΩ)을 통한 극미량의 전류만 흐르게 되어, LED가 켜지지 않거나
매우 희미하게만 점등되는 오동작이 발생한다. GPIO를 출력으로 쓰려면 DDRx와
PORTx를 모두 설정해야 한다는 점을 놓친 전형적인 실수다.

**해결 과정**:
1. `avr-objdump -d`로 컴파일된 명령어 목록에서 DDRA(0x1a) 접근이 없음을 확인해 의심 지점을 좁혔다.
2. `gpio_init()`에 `LED_DDR |= LED_ALL;`을 추가했다.
3. 재빌드 후 `avr-objdump -d`로 다시 확인한 결과, DDRA(0x1a)에 대한 `in`/`out` 명령이 생성된 것을 확인했다.
   ```
   a8: 8a b3  in  r24, 0x1a
   ac: 8a bb  out 0x1a, r24
   ```

## 시뮬레이션 검증 결과

**확인해야 할 시뮬레이션 시나리오** (Proteus/SimulIDE):
1. ATmega128에 PA0-PA2를 각각 저항을 거쳐 LED(정상/주의/경보)에, PD4를 부저(또는 스피커)에 연결한다.
2. 수정 전(`2066243` 커밋) `.hex`를 로드해 실행 → LED가 켜지지 않거나 매우 희미하게만 켜지는지 확인
3. 수정 후(`b8e3007` 커밋) `.hex`를 로드해 실행 → 정상(1초) → 주의(1초) → 경보+부저(1초) 순으로 LED가 뚜렷하게 순환 점등하는지 확인

> 위 시나리오는 아직 사용자 확인 전입니다. 직접 실행하신 결과를 알려주시면 이 절을 업데이트하겠습니다.
> (참고: `avr-objdump` 어셈블리 분석으로 DDRA 설정 누락/수정 자체는 코드 레벨에서 확정적으로 검증했습니다.)
